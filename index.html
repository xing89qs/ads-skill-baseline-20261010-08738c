          06 / 优化后对照协议

          维度原始基线优化后
          1. 决策回放：用完全相同的冻结 A/A2、目标和约束，开隔离的新 bundle。对照数据哈希；不要让评估 agent 看六条基线答案。
          2. 端到端重跑：单独测量 fresh pipeline；注明 API 缓存、模型版本、窗口和数据变化，不能把只跑 B 的耗时拿来和完整原始 run 比。
          3. 质量不退化：保留对象 / action-family 覆盖、真实 ID、证据时间窗、高风险规则、审批 gates；独立判断动作是否合理，不以“与六条答案完全一致”为唯一正确标准。
          4. 观察语义：更多候选 / 更少动作本身不代表更好；检查保留对象是否有证据、是否漏掉 wanted-active / 高花费控制义务。
          5. Jev 单独评测：记录 API 延迟、费用、question/model 版本、失败与低置信度 fallback、选项顺序稳定性；保留稀有和高风险边界案例。
          6. 版本覆盖：通用行为改 base，让 Codex / Luckee 消费一致；仅多 agent 差异改 overlay；改 shared/scripts 同步 pytest，不靠跳过 validator 提速。
