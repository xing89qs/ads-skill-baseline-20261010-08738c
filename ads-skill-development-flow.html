Luckee 广告 Skill 开发与工作区发布流程

从修改 Skill，到创建评估 working_dir，再到让新建 Luckee 工作区自动拿到新版本的完整操作手册。

适用仓库：luckee-ads-skills　|　适用日期：2026-10-14　|　覆盖 V2 eval、Luckee 2.0 多 Agent 工作区和内容 CDN

1. 修改 base编辑 skills/、shared/
2. 生成 Luckee 树更新 mapping/overlay 物化结果
3. 构建内容包发布 dev/prod immutable bundle
4. Seed / 热更新新工作区自动应用，旧工作区按需更新

一、先区分两条链路

场景入口产物用途
本地评估 / Codex 试跑luckee-ads-eval/scripts/seed_workspace.py/tmp/eval-runs/ws-<case>/working_dir从 case 生成隔离、可重复的测试工作区
Luckee 2.0 新工作区pnpm --filter @luckee/backend seed:amazon-ad-workspace$HOME/.luckee/workspaces/<workspace-id>创建线上/本地多 Agent 工作区
已有 Luckee 工作区更新Content Update API / UI / CDN latest.luckee/skills、Agent skill home、协议文件不删除产品运行数据地更新内容
不要混用：eval seeder 的 working_dir 不是 Luckee 线上 workspace。前者直接拷贝仓库内容；后者通过 vendored submodule、mapping.json、skill materializer 和内容 CDN 生成。

二、如何 seed 一个 eval working_dir

1. 准备 case

cd /path/to/luckee-ads-skills
python3 luckee-ads-eval/scripts/seed_workspace.py --list

case 至少应包含 case_manifest.json 和 input/。只把产品配置、目标、MCP route、task 等放进 input/；judge_only/ 永远不能进入 agent 工作区。

2. V2 fresh seed

CASE_ID=b0gtk8mp5y-workspace-config-v2-001
OUT=/tmp/eval-runs
WORKER=/home/dylan/apps/core-agent-loop-worker/ts_luckee

python3 luckee-ads-eval/scripts/seed_workspace.py "$CASE_ID" \
  --harness v2 \
  --phase-a-mode fresh \
  --out "$OUT" \
  --trust \
  --force \
  --validated-json-worker-root "$WORKER"

结果目录是 $OUT/ws-$CASE_ID/，Codex 应从其中的 working_dir 启动：

cd "$OUT/ws-$CASE_ID/working_dir"
codex exec --sandbox workspace-write \
  --dangerously-bypass-hook-trust \
  "$(cat "$OUT/ws-$CASE_ID/.luckee-eval/prompt.md")"
  • --fresh / --phase-a-mode fresh：不复制旧快照，要求 agent 重新完成 Phase A/A2。
  • --force：覆盖 disposable seed 目录；覆盖前应先备份。
  • --trust：把项目写入 Codex trusted projects，否则项目级 MCP 配置可能被忽略。

3. 验收 seed

python3 - <<'PY'
import json
from pathlib import Path
root = Path(".")
meta_path = next(root.glob("products/*/product_meta.json"))
print("product:", json.loads(meta_path.read_text()).get("primary_asin"))
manifest = json.loads(Path("../.luckee-eval/manifest.json").read_text())
print("phase_a_mode:", manifest["phase_a_mode"])
print("validated_json_mcp_configured:", manifest["validated_json_mcp_configured"])
PY

codex mcp list
find products -type f \( -name snapshot_meta.json -o -name decision.json \)
fresh 验收：phase_a_mode=fresh，初始没有 snapshot/decision；先由 agent 跑 pipeline，再生成这些产物。

三、如何保证 Luckee MCP 进入 working_dir

1. 三类 MCP 来源

类型例子配置位置作用
产品数据 MCPxingshang_<scope>、lingxing_<scope>case 的 input/system_state/mcp-data-routing.json，seed 时合并到 .codex/config.toml / .mcp.json广告指标、关键词、搜索词、placement、listing 等
本地写入 MCPwrite-validated-json.codex/config.toml、.mcp.json、.codex/tools/Schema 校验后写入受保护 JSON
Luckee 运行时 MCPluckee_orchestrator、ApprovalsLuckee backend/worker 注入，不由 eval case 伪造委托 Agent、审批同步、平台编排

2. validated JSON 的实际接入

eval seeder 不复制整个 worker，而是把桥接器复制到工作区，并用本机 worker 的 tsx 启动：

Codex
  └─ STDIO MCP: write-validated-json
      └─ validated_json_stdio_bridge.mts
          └─ worker/src/mcp/write-validated-json-sdk-server.ts
              └─ Schema validation + JSON write

桥接器会校验 output_path、schema_path、payload_path 必须在当前 WORKING_DIR 内，且拒绝软链接逃逸。当前支持：

{
  "output_path": "products/P/targets/current_period.json",
  "payload_path": "input/target.json",
  "schema_path": "shared/schemas/workspace_operational_goal.schema.json"
}

payload 与 payload_path 必须二选一；schema 与 schema_path 也必须二选一。

3. 已有 working_dir 补接 MCP

python3 luckee-ads-eval/scripts/attach_validated_json_mcp.py \
  /tmp/eval-runs/ws-$CASE_ID/working_dir \
  --validated-json-worker-root /home/dylan/apps/core-agent-loop-worker/ts_luckee

补接后必须重启 Codex task。检查：

grep -A6 'write-validated-json' .codex/config.toml
cat .codex/tools/validated-json-provenance.json
tsx .codex/tools/validated_json_stdio_bridge.mts \
  /home/dylan/apps/core-agent-loop-worker/ts_luckee . --check
不要只看文件：配置存在不代表当前会话已加载。Codex App 要从该 working_dir 新建 task；旧 task 不会热加载新的 skill/MCP。

四、修改 Skill 的正确分层

改动应修改位置是否生成 Luckee 树
Codex 与 Luckee 共用行为skills/<slug> 或 shared/若只影响 symlink/base，通常自动跟随；若要发布 Luckee，仍需构建内容包
Luckee 多 Agent 特有委托规则luckee2.0/<agent>/<skill>/LUCKEE_OVERLAY.md必须运行 apply-luckee-overrides.mjs
带开发机路径/内部 URL 的 sanitized skill修改 base 或生成器的 sanitize rules必须重新生成物化树
Luckee 专属 skillluckee2.0/ 中真实文件按映射登记并重新生成
node luckee2.0/tools/apply-luckee-overrides.mjs
git diff -- luckee2.0/
git add luckee2.0/

mapping.json 决定 Agent → skill 的绑定、override、sanitized 和 variants。不要手工改生成后的 Luckee 物化拷贝。

五、让新 Skill 在新 Luckee 工作区生效

路径 A：直接重新 seed（本地 / 开发机）

cd ~/apps/luckee2.0
git submodule update --init apps/backend/vendor/luckee-ads-skills

pnpm --filter @luckee/backend seed:amazon-ad-workspace -- \
  --workspace-id amazon-ad-B0GTK8MP5Y \
  --source-path /absolute/path/to/luckee-ads-skills

seed 脚本从 pinned 的 vendor/luckee-ads-skills 读取 luckee2.0/mapping.json，物化 skill 到 .luckee/skills/，再按 Agent binding 复制到 agents/<agentId>/.claude/skills/；Codex runtime 还会复制到 .codex/skills/。

如果只想刷新 Skill、协议和 hooks 而保留产品数据，加 --skip-products。如果需要重建 custom Agent persona，加 --reset。

路径 B：发布内容包，让新工作区自动应用

Luckee 2.0 的 provision 流程在配置 LUCKEE_CONTENT_CDN_BASE_URL 时，会在新工作区成功前应用 channel latest。内容包是不可变的；任何修改都必须创建新版本。

cd ~/apps/luckee2.0
pnpm --filter @luckee/backend content-bundle:build -- \
  --out dist/content-bundles/dev-abc123-20261014T120000Z \
  --version dev-abc123-20261014T120000Z \
  --channel dev \
  --source-commit <skills-commit> \
  --release-tag v2026.10.14 \
  --deps shared/rules/action-observation-separation.md

构建器默认读取 apps/backend/vendor/luckee-ads-skills；本地验证或临时发布可用 --fixture /absolute/path/to/luckee-ads-skills。依赖必须是 skills 根目录下的相对 shared/ 路径。

发布后原子更新：

channels/dev/latest.json
{
  "contentVersion": "dev-abc123-20261014T120000Z",
  "path": "bundles/dev-abc123-20261014T120000Z/content-bundle-dev-abc123-20261014T120000Z.tar.gz",
  "sha256": "<manifest.json 中的 sha256>"
}

新工作区会在 provision 时应用最新包；已有工作区需要在 UI 的内容更新入口或 Content Update API 中执行 check/apply。

六、Skill 内容包必须包含什么

  • working_dir_skills/：工作区归档的 skills/ 内容。
  • luckee_skills/：Luckee API / Agent skill home 使用的 skill 内容。
  • bindings.json：Agent slug 到 skill slug 的绑定。
  • agents_md/、files/：协议文件和显式 shared 依赖。
  • manifest.json、mcp_routing/：版本、校验、路由 profile。
关键点：只改 skills/ads-tuner 但不更新 bindings.json 或依赖文件，可能导致 Skill 文件已发布但没有绑定到对应 Agent，或者新 Skill 引用了工作区中不存在的 helper。

七、发布前验收清单

  1. Skill base、overlay、sanitized 规则改在正确层；没有手改生成物。
  2. 运行 node luckee2.0/tools/apply-luckee-overrides.mjs，检查 luckee2.0/。
  3. 执行对应单元测试、Skill contract audit 和 git diff --check。
  4. eval fresh seed 一个工作区，确认新 Skill 与所有依赖脚本存在。
  5. 确认 .codex/config.toml / .mcp.json 包含产品 MCP 和 write-validated-json。
  6. 对 write_validated_json 做 --check，另测 inline payload 和 payload_path。
  7. 构建内容包，核对 manifest checksum、source commit、release tag。
  8. 先发 dev，创建新 Luckee 工作区做 smoke test，再晋升 prod。
  9. 检查新工作区的 .luckee/skills、Agent skill home、AGENTS.md、.mcp.json 和 installed content version。
  10. 确认新建聊天线程从正确工作区启动；旧 task 不会自动加载新 skill。

八、常见故障定位

现象优先检查
Skill 不出现是否从 seeded working_dir 新建 task；mapping.json 是否绑定该 Agent；Luckee Agent home 是否有 skill。
MCP 配置存在但工具列表没有Codex project trust、当前 task 是否旧会话、MCP command/cwd 是否指向实际 working_dir。
write_validated_json 写入失败worker root、tsx、schema、payload_path 是否在工作区内；不要用 raw Write 绕过。
新建 Luckee 工作区仍是旧 Skillvendor submodule 是否更新；内容 CDN latest 是否指向新版本；provision 是否应用成功；检查 installedVersion/lastError。
Skill 文件更新但 Agent 不生效bindings.json 是否包含 Agent slug；content update 只增不减，必要时发布新 contentVersion 并重新 apply。
改了 base 但 Luckee 没变化是否重新生成 overlay/物化树，是否重新构建并发布 immutable bundle；不要覆盖旧 bundle。

九、推荐的最小发布命令集

# 1) 本地检查
git status --short --branch
node luckee2.0/tools/apply-luckee-overrides.mjs
python3 shared/scripts/audit_ads_tuner_contract.py --strict
git diff --check

# 2) eval smoke seed
python3 luckee-ads-eval/scripts/seed_workspace.py <case-id> \
  --harness v2 --fresh --trust --force \
  --validated-json-worker-root /home/dylan/apps/core-agent-loop-worker/ts_luckee

# 3) Luckee 本地新工作区
cd ~/apps/luckee2.0
git submodule update --init apps/backend/vendor/luckee-ads-skills
pnpm --filter @luckee/backend seed:amazon-ad-workspace -- \
  --workspace-id amazon-ad-<ASIN> \
  --source-path /absolute/path/to/luckee-ads-skills

本手册对应的实现依据：luckee-ads-eval/scripts/seed_workspace.py、validated_json_mcp.py、validated_json_stdio_bridge.mts，以及 ~/apps/luckee2.0/apps/backend/scripts/seed-amazon-ad-workspace.ts、build-workspace-content-bundle.mjs、workspace-content-update/。
